Role Profile and Competency Library — data architecture

Ten tables in one scoped application. Five kinds of governed content extend one base table that carries the shared lifecycle. The Competency Library runs from Competency Group to Domain to Element. Proficiency Level descriptors sit on the Element, or on the Domain for the lower levels of Cross-Cutting Domains. Role Profiles point into the library at Element level, with a Target PL on every requirement.

Versioning and effective dating

Record lifecycle

Draft→ Published→ Retired

Publishing needs an Effective From date, a Published Framework Version and a Published parent. Published content columns are frozen. A Retired record cannot be reinstated.

To change Published content, Create New Version copies it to a Draft that supersedes the original. Publishing the Draft end-dates the original instead of overwriting it.

Example: Engineer – Application Development

JanMarMayJulSepNov
v1 · Published · to 30 Jun
v2 · Published · from 1 Jul

Both versions stay Published. Employees see v2 because it is the one effective today; v1 remains intact for history and for any record that refers to it.

Integrity rules enforced on the server

Descriptors follow the Domain's structureCross-Cutting Domains describe PL1–PL2 once for the Domain and PL3+ per Element; Specialised Domains describe every level per Element. An Element shows its Domain's levels and its own.
Target PL lives on the requirementElements in the same Domain can have different targets. The target must be a level the Element defines, its own or inherited from its Domain.
No Draft content behind Published profilesA Role Profile publishes only when every Element is Published, in its Framework Version, with a Published descriptor at the Target PL.
No overlapping Published versionsSame code and Framework Version, or same Element and PL, cannot have two Published rows effective on one day.
One active Draft per Element and PLDuplicate Draft descriptors for the same Element, PL and Framework Version are rejected.
Recommended limits warn, not block3–5 Essential and up to 12 requirements are system properties. A switch makes them blocking if policy requires it.
Employees see only Published contentAccess controls hide Draft and Retired rows. Browse and search also filter to what is effective today.
